# MVP 스펙: 빠른 메모

## 가설
개인 사용자가 떠오른 생각을 한 화면에서 바로 적고 같은 화면에서 다시 볼 수 있으면, 생각을 잊지 않으려고 이 도구에 메모를 남길 것이다.

## 핵심 흐름 (번호 순서)
1. 사용자가 로컬에서 앱을 실행하고 브라우저로 메인 페이지를 연다.
2. 입력란에 메모 내용을 적는다.
3. 추가 버튼을 누르거나 Enter를 친다.
4. 방금 쓴 메모가 같은 페이지의 목록에 나타난다.
5. 페이지를 새로고침하거나 앱을 껐다 다시 켜도 목록에 메모가 그대로 남아 있다.

## 포함 기능 (기능 - 없으면 끊기는 이유)
- 메모 입력란과 추가 동작 - 없으면 메모를 적을 수 없어 흐름 2~3단계가 성립하지 않는다.
- 메모 목록 표시 - 없으면 적은 메모를 다시 볼 수 없어 흐름 4단계가 성립하지 않는다.
- 로컬 영구 저장 (파일 또는 SQLite) - 없으면 새로고침/재시작 시 메모가 사라져 흐름 5단계가 성립하지 않는다.
- 로컬 실행 명령 하나 - 없으면 사용자가 흐름 1단계에서 앱을 열 수 없다.

(대체 수단 확인: 계정은 고정 단일 사용자로 대체했고, 저장소 설정은 설정 없는 파일/SQLite로 대체했다. 위 4개는 수작업이나 하드코딩으로 대신하면 가설을 검증할 수 없어 유지한다.)

## 제외 기능 (기능 - 제외 이유)
- 로그인/계정 - 사용자가 개인 한 명이므로 고정 사용자로 충분하다. 인터뷰에서 제외 확정.
- 검색 - 메모를 적고 보는 흐름은 검색 없이 된다. 인터뷰에서 제외 확정.
- 수정 - 추가와 확인만으로 가설 검증이 된다. 인터뷰에서 제외 확정.
- 삭제 - 추가와 확인만으로 가설 검증이 된다. 인터뷰에서 제외 확정.
- 태그 - 분류 없이도 흐름이 된다. 인터뷰에서 제외 확정.
- 배포 - 로컬 실행으로 충분하다. 인터뷰에서 제외 확정.
- 입력 검증 외 부가 UI (스타일링, 정렬 옵션, 페이지네이션) - 흐름에 영향이 없다.

## 나중에
- 삭제와 수정 (메모가 쌓이면 정리 수단이 필요해짐)
- 검색 (메모 수가 많아지면 필요해짐)
- 태그
- 작성 시각 표시

## 성공 기준 (실행으로 확인 가능한 문장)
1. 문서에 적힌 실행 명령 하나로 앱이 뜨고, 브라우저에서 메인 페이지를 열면 입력란, 추가 버튼, 메모 목록 영역이 보인다.
2. 입력란에 "테스트 메모 1"을 적고 추가하면, 페이지 이동 없이(또는 이동 후 같은 페이지에서) 목록에 "테스트 메모 1"이 나타난다.
3. 추가 후 입력란은 비워진다.
4. 메모 두 개를 추가하면 목록에 두 개가 모두 보이며, 최신 메모가 맨 위에 있다.
5. 빈 입력(공백만 포함)으로 추가하면 목록에 항목이 생기지 않는다.
6. 브라우저를 새로고침해도 앞서 추가한 메모가 목록에 그대로 보인다.
7. 앱 프로세스를 종료하고 같은 명령으로 다시 실행한 뒤 페이지를 열어도 앞서 추가한 메모가 목록에 그대로 보인다.
8. 실행에 필요한 도구는 node, npm, python3, uv 중에서만 쓰며, 새 도구 설치 없이 위 1~7이 통과한다.

## 가정 (확인 필요 여부 표시)
- 인터뷰 전체가 루프 자동 진행용 기본값이다. 실제 사용자 확인을 거치지 않았다. (확인 필요 - 단, 시험용 MVP이므로 진행에는 지장 없음)
- 인터페이스는 로컬 웹 페이지(브라우저)로 가정했다. 인터뷰의 "새로고침" 표현에서 추론했다. CLI로 바뀌면 성공 기준 1, 2, 6이 바뀐다. (확인 필요)
- 목록 정렬은 최신 메모가 맨 위로 가정했다. 성공 기준 4에 영향. (확인 필요 - 경미)
- 빈 입력은 무시하는 것으로 가정했다. 성공 기준 5에 영향. (확인 필요 - 경미)
- 메모는 한 줄 이상 텍스트만 다루며 길이 제한은 두지 않는다. (확인 불필요)
- 저장 방식(파일 또는 SQLite)과 구체적 스택 선택은 설계 단계에 맡긴다. 인터뷰 범위 안에서 어느 쪽이든 성공 기준은 같다. (확인 불필요)
- 단일 사용자, 단일 브라우저 탭 사용을 가정하며 동시 쓰기 충돌은 고려하지 않는다. (확인 불필요)
